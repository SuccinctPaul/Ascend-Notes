# 构建与部署说明

本仓库使用 [Vocs](https://vocs.dev)（React + Vite 驱动的静态文档生成器）构建文档站点，部署到 GitHub Pages。

---

## TL;DR

```bash
npm install --legacy-peer-deps   # 安装依赖
npm run dev                      # 本地预览 (http://localhost:5173)
npm run build                    # 构建静态站点 → dist/
```

---

## 前置条件

1. **Node.js 22+**（推荐用 [fnm](https://github.com/Schniz/fnm) 或 [nvm](https://github.com/nvm-sh/nvm) 管理）
2. **npm**（随 Node.js 安装）

## 1. 本地预览

```bash
npm install --legacy-peer-deps
npm run dev
```

浏览器打开 `http://localhost:5173`，修改 `docs/pages/` 下的文件会自动热刷新（`vocs.config.ts` 里 `srcDir: 'docs'` 指向它）。

## 2. 本地构建

```bash
npm run build
```

构建产物在 `dist/public/` 目录（纯静态 HTML/JS/CSS），可直接用 `npm run preview` 预览构建结果。

> `vocs.config.ts` 中设置了 `renderStrategy: 'full-static'`，确保输出纯静态文件以适配 GitHub Pages。

## 3. 部署到 GitHub Pages

### 3.1 GitHub 仓库设置

1. 打开仓库 **Settings → Pages**
2. **Source** 选择 **GitHub Actions**（不是 Deploy from a branch）
3. 保存

### 3.2 自动部署

仓库已配置 [GitHub Actions workflow](https://github.com/SuccinctPaul/ascend-handbook/blob/main/.github/workflows/deploy-docs.yml)，
每次 push 到 `main` 分支会自动：

1. 安装 Node.js 22 + npm 依赖
2. 执行 `npx vocs build` 构建静态站点
3. 将 `dist/` 上传为 Pages artifact
4. 部署到 GitHub Pages

部署完成后，站点地址为：
```
https://succinctpaul.github.io/ascend-handbook/
```

> **注意**：`vocs.config.ts` 中的 `basePath: '/ascend-handbook'` 必须与你的仓库名一致。
> 如果你把仓库改名为 `my-docs`，`basePath` 也要改成 `'/my-docs'`。

### 3.3 手动触发部署

在 GitHub 仓库的 **Actions** 页，找到 "Deploy docs to GitHub Pages" workflow，点 **Run workflow** 即可手动触发。

│   ├── pages/                           # 文档页面（文件路由）
│   │   ├── index.mdx                    # 首页（landing 布局）
│   │   ├── hardware/                    # 第 01 卷 · NPU 体系化架构
│   │   ├── perf/                        # 第 02 卷 · 性能模型与 Profiling
│   │   ├── dsl/                         # 第 03 卷 · 四种 DSL 核心手册
│   │   ├── ops/                         # 第 04 卷 · LLM 优化算子
│   │   ├── reference/                   # 术语表
│   │   └── deployment.mdx              # 本文件
├── public/                              # 静态资源（图片等，Vocs 约定在项目根）
├── examples/                            # 四种 DSL 的可运行 kernel 与基准脚本
├── scripts/                             # check-mdx.mjs 等构建辅助脚本

> 图片等静态资源放在项目根的 `public/`（Vocs 约定位置），Markdown 里用站点绝对路径引用（如 `/ascend-handbook/cube-unit-16x16.png`，前缀是 `basePath`）。

## 5. NPU 开发环境（算子开发侧）

本页上面讲的是"文档站"的构建部署；要**跑 `examples/` 里的 NPU kernel**，需要的是另一套环境：

1. **硬件**：Ascend 910B 系列 NPU（仓库实测 Ascend 910B2）。
2. **驱动与 CANN**：CANN 9.0.0（每个 shell 先 `source /usr/local/Ascend/ascend-toolkit/latest/set_env.sh`）。
3. **Python 系 DSL**（python / triton_ascend / tilelang_ascend）：各自目录 `uv sync` 建 venv，torch / torch_npu / triton-ascend / tilelang-ascend 的版本锁见各目录 README 与 `pyproject.toml`。
4. **C++ DSL**（ascend_c）：CMake + CANN 的 `ascendc.cmake` 框架，构建命令见 [Ascend C 手册 §3.4.5](/dsl/04-ascend-c)。

> **一键安装**：以上环境可用 `scripts/` 下的脚本复现 ——
> `sudo ./scripts/install_npu_toolchain.sh`（CANN toolkit 自动下载安装，驱动/固件可选）+
> `./scripts/install_dsl_envs.sh all`（四种 DSL 环境，支持 `python | ascend_c | triton | tilelang | verify` 单独安装）。

常见运行期故障（`E39007`、`rtSetDevice 507033`、HDC 链路 hang、`ACL_OP_INIT_MODE=1` 等）
的排查清单见 [GELU 篇 §8.10](/ops/05-gelu) 的验证步骤与常见坑总表。

## 6. 常见问题

### Q: `npm install` 报 peer dependency 冲突？

A: 加 `--legacy-peer-deps`：
```bash
npm install --legacy-peer-deps
```

### Q: Mermaid 图不渲染？

A: Vocs 原生支持 Mermaid（通过 `rehypeMermaid` 插件），无需额外配置。只需在 Markdown 中使用：

````
```mermaid
flowchart LR
  A --> B
```
````

注意：`npm run dev` 使用的是自定义启动脚本 `scripts/dev-vite.mjs`（而非 `vocs dev`），
它注入了 `optimizeDeps: { include: ['mermaid'] }`。原因：vocs 客户端动态 `import('mermaid')`，
而 rolldown-vite 对这条链不做运行时依赖预构建，mermaid 的 CJS 依赖 dayjs（只有 UMD 入口）
会被原样发给浏览器，报 `does not provide an export named 'default'` 导致图不渲染。
预构建后 dayjs 被转成 ESM 一并打包，问题消失。若未来 vocs 原生修复，可把 dev 脚本改回
`vocs dev` 并删除该文件。

### Q: 如何修改 sidebar 导航？

A: 编辑 `vocs.config.ts` 中的 `sidebar` 配置。

### Q: 如何修改主题色/Logo？

A: 编辑 `vocs.config.ts` 中的 `iconUrl`、`logoUrl` 等配置项。参见 [Vocs 配置文档](https://vocs.dev/docs/api/config)。
